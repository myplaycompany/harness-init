# DOMAIN.md 운영 규칙

`DOMAIN.md` 는 **의미(semantics) 전용 문서**다. 구조는 codegraph가 담당한다.
역할 분담 전체는 `@.claude/rules/knowledge.md` 참조.

## 무엇을 적고 무엇을 적지 않는가

| 적는다 | 적지 않는다 (codegraph에 물어볼 것) |
|--------|-----------------------------------|
| 상태값이 무슨 뜻이고 언제 전이하는가 | 모델·함수가 어디 있는가 |
| 시그널이 무슨 부수효과를 내는가 | 누가 무엇을 호출하는가 |
| 도메인 용어·팀 내부 슬랭 | 필드 목록·타입·FK 관계 |
| 여러 모듈에 흩어진 비즈니스 규칙 | 계층 트리·의존 그래프 |
| 과거 사고 지점 (변경 시 주의사항) | 이걸 바꾸면 어디가 깨지나 |
| 모델 → 실제 테이블명 매핑 | |

**구조를 문서에 박제하지 마라.** 그 순간부터 낡는다. 코드가 진실의 원천이고,
코드에서 재도출 가능한 것은 재도출한다.

## 에이전트별 의무

| 에이전트 | 의무 |
|---------|------|
| **analyst** | 구조 파악은 codegraph 우선. 작업 대상 도메인의 `DOMAIN.md`에서 상태값 의미·시그널 부수효과·용어를 확인. 모델을 건드리는 작업이면 **시그널 표 확인은 필수** |
| **coder** | 의미가 바뀌는 변경(Choices 값·시그널·db_table)을 했으면 같은 커밋에서 `DOMAIN.md` 갱신. 변경 이력 표에 한 줄 추가 |
| **reviewer** | 의미 변화 대비 문서 갱신 여부를 **게이트로 검증**. 미갱신은 PASS 불가 |

## 갱신 트리거

게이트가 자동으로 잡아주지만, 무엇이 트리거인지 알고 움직인다.

```
Choices/Enum 값 추가·삭제·변경  → 상태값 표의 '의미 / 전이 조건' 채우기
@receiver / signal.connect 변경 → 시그널 표의 '무슨 부수효과를 내나' 채우기
Meta.db_table 변경              → 모델 → 테이블 매핑 표 갱신
새 도메인 용어·슬랭 등장         → 루트 DOMAIN.md 용어 사전
사고·장애가 났던 지점            → '변경 시 주의사항'
```

앞의 셋은 `domain-gate.py` 가 AST 비교로 정확히 감지해 커밋을 막는다.
뒤의 둘은 기계가 알 수 없으니 사람과 에이전트가 판단해서 남긴다.

## 값 목록은 손으로 적지 마라

Choices·Enum·db_table 의 **값과 위치**는 기계가 뽑는다. 손으로 옮겨 적으면 틀린다.

```bash
python3 .claude/scripts/domain-extract.py . --app <앱경로> --format md
```

출력을 참고해 표를 맞추고, 사람은 **'의미' 열만** 채운다.

## DOMAIN.md가 없거나 낡았을 때

```bash
# 스켈레톤 생성 (이미 있으면 건너뜀)
bash ~/harness-init/scripts/domain-init.sh

# 신선도 점검 — 소스보다 며칠 뒤처졌는지
python3 .claude/scripts/domain-freshness.py .
```

세션 시작 시 낡은 문서 목록이 컨텍스트로 자동 주입된다.
그 목록에 있는 문서의 내용은 **근거로 쓰기 전에 코드로 교차 확인**한다.
